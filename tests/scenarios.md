# Platform extension scenario walkthroughs

Reviewed 2026-10-01 by the authoring assistant against SKILL.md and its references. These are manual instruction-level walkthroughs: no independent-agent benchmark or native runtime test was performed. They document the next appropriate action and expose scope errors before distribution.

| Request and supplied context | Walkthrough result | Boundary checked |
| --- | --- | --- |
| Three-page HTML/CSS/JS blue dragon portfolio; Yue; audience and original images known | Website lane; work from established brief and keep the existing web approach. Contact omission remains honored. | No new app framework, re-interview, or invented art evidence. |
| "Make me a dragon app"; no repository or purpose | Ask what it helps people do and where it should run; then ask remaining consequential context. | Do not choose a native toolkit or build a decorative dashboard before knowing the job. |
| Flutter Android journal; local offline entries; supplied artwork; user delegates routine decisions | Mobile lane and Flutter notes; proceed with a focused entry/list flow, real local persistence, and touch-safe motif treatment. | Android only; no repeated target question, cloud backend, mandatory router, or cursor trail on touch. |
| React browser task board in an existing repository; real API specified | Web lane; preserve stack and API, define task transitions, failed saves, empty results, meaningful routes, and narrow layouts. | Do not replace the working application with a marketing page. |
| JavaFX inventory app; user requests a master prompt only | Desktop lane; produce a standalone prompt with supplied facts, window/task structure, toolkit resources, background-work constraints, and verification criteria. | No implementation or silent Swing conversion. |
| Existing Swing catalog; redesign while preserving file loading | Desktop lane; retain Swing and current model, use layout managers and Actions, preserve loading behavior and avoid blocking the EDT. | JavaFX/CSS guidance is not applied literally to Swing. |
| MAUI phone app; existing Shell; Windows development host; Android and iOS requested | Mobile lane plus shared MAUI notes; preserve Shell and targets, perform available checks and report unavailable iOS execution. | Browser preview cannot establish native coverage; Windows does not imply iOS runtime verification. |
| Avalonia desktop organizer with custom theme and ViewModels | Desktop lane; retain theme, resource layering, bindings, keyboard flow, and resize behavior. | Do not force Fluent or add a replacement architecture. |
| Flutter app for browser and desktop; navigation addresses are required | Web and desktop lanes plus Flutter notes; specify addressable navigation and verify each requested target separately. | Shared code does not prove both runtimes were tested. |
| Clear mobile app brief, missing decorative images, user asks to generate fitting artwork | Carry forward the brief and generate relevant artwork with an available tool; otherwise provide prompts and mark assets pending. | Do not restart discovery, claim nonexistent generation, or turn raster art into fake user work. |
